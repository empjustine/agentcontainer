# d056 — coding-agent/run.sh: directory mounts replace the generator tree and CODING_AGENT_REFERENCES

**Status: implemented.** `coding-agent/run.sh` now takes
`[DIRECTORY [DIRECTORY...]]`, with CWD as the implicit first directory. Every
directory is mounted read-write at its own host path, the first is the
container workdir, and a directory resolving to `$HOME` is refused. The
generator tree and `/opt/lib` module mounts are gone, as are the
`PEER_BASE_URL`/`PEERS_ONLY` env forwards; the `CODING_AGENT_REFERENCES`
toggle that used to bind-mount `~/Downloads/references` is gone too — the
mirror is passed as just another `DIRECTORY`.

## Problem

Three separate seams had accumulated in the runner:

1. **The runner carried generator support into the sandbox.** Despite
   docs/d041 ("runners never build or generate"), `run.sh` mounted the
   generator tree file by file (two generators + `gen-lib.mjs` + four helper
   modules + caches) plus the whole `../lib` module list under `/opt/lib`, only
   so an in-container session could regenerate manually via
   `/opt/coding-agent/generate.sh`. That is a second copy of
   `generate.mjs`'s scratch-staging list, hand-maintained in shell, and every
   missing entry was a latent `ERR_MODULE_NOT_FOUND` for a path the runner no
   longer needs. The env allowlist also forwarded `PEER_BASE_URL` and
   `PEERS_ONLY`, which only the GENERATOR reads — pi resolves the baked
   `baseUrl` from `models.json`, not from the environment.
2. **`CODING_AGENT_REFERENCES` was a one-off toggle.** A single optional
   ro-mount hard-coded the reference-farm path and made the whole feature
   invisible in the ARGV. The 1.66M-file / ~39 s `z,U` relabel cost the
   toggle guarded against is real, but a hidden env var is the wrong control:
   the operator already names the directories a run should see.
3. **The ARGV was ambiguous.** The old runner consumed an optional first
   positional as the workspace and forwarded the rest to pi; the current one
   dropped the rest of the argv into interactive `bash`. Neither made the
   argument list do anything the operator could read off the command line.

## Decisions

### (a) No generator support in the runner

`run.sh` mounts only what a *runtime* needs: the host agent dir, the per-run
session stage, the other harness state dirs, and `lib/log.sh` for the launch
chain's logger. The `/opt/coding-agent` tree and the `/opt/lib` module list
are removed. An in-container session works against the host-generated config;
regeneration is host-side (`./generate.sh` / the root `./generate.sh`). The
docs/d041 "no retry loop" message stays: a missing installed artifact is a
loud failure pointing at the generator, never an implicit regeneration. The
`PEER_BASE_URL` / `PEERS_ONLY` forwards are removed with the generator — pi
never read them.

The `tests/lib-staging.test.mjs` run.sh half of the guard is deleted; only the
`generate.mjs` scratch-staging list remains hand-maintained, and it now has
one home.

### (b) ARGV is the mount list

```
run.sh [DIRECTORY [DIRECTORY...]]
```

- **CWD is the implicit first `DIRECTORY`** (decision c.2). It is prepended to
  the argument list, so there is no separate workspace parameter and passing
  `.` explicitly is a harmless duplicate (the list is deduplicated).
- **Every directory is mounted rw at its own host path**, and the first is the
  workdir. There is no per-directory mode flag: a directory the sandbox may
  read but not write was not a use case the runner needed (the reference farm
  is regenerated by host-side `git/` tooling, not by the agent).
- **`$HOME` is refused** (decision c.1). The resolved path of every directory
  is compared against the resolved `$HOME`; the check is uniform across the
  container and Termux branches, so `run.sh` from `$HOME` still fails (as the
  old container branch did).
- **`~/Downloads/references` becomes an ordinary directory** (decision c.3):
  `./run.sh ~/Downloads/references`. The `CODING_AGENT_REFERENCES` branch, its
  header docs, and the "off by default" rationale are deleted. The relabel
  cost is not gone — it is now paid only when the operator types the path,
  which is the same opt-in the toggle encoded, minus the hidden control.
- **Termux has no mount boundary.** The directories are already visible there
  at their real paths, so only the first (the `cd` target) changes anything.
  The pi argv is no longer forwarded: `run.sh` is a directory launcher, not a
  pi flag pass-through.

### (c) Dedup keeps the first occurrence

The list is resolved (`pwd -P`) and deduplicated in one pass, preserving
order: the first occurrence wins, so a later duplicate can never displace the
implicit CWD from position one. This keeps `run.sh .` and `run.sh $(pwd)` a
single mount rather than a podman duplicate-destination error.

## Invariants and consequences

- **The runner no longer mirrors `generate.mjs` staging.** Adding a generator
  module means editing `generate.mjs`'s staging list only; `run.sh` does not
  care. `tests/lib-staging.test.mjs` now guards exactly that one list.
- **In-container regeneration is intentionally gone.** The host agent dir is
  still mounted rw, so an in-container edit to `settings.json`/`models.json`
  persists — but there is no generator to re-derive them. Host-side
  regeneration remains the documented path (docs/d041).
- **The directory list is the mount manifest.** `workload_rw` is called once
  per unique directory; `workload_workdir` is the first. The old `references`
  ro-mount is now an rw mount when named — the mirror's read-only posture was
  a property of the retired special case, not a new guarantee.
- **`$HOME` under a different symlink spelling is still refused** because both
  sides are resolved with `pwd -P`; a directory *under* `$HOME` (a project in
  `~/code/...`) is allowed.
- **`docs/d043`'s description of the toggle is historical.** That record's
  body is not rewritten (d042); this record is the tombstone for the env var.

## Alternatives considered

- **Keep the generator mounts and just drop `PEER_BASE_URL`.** Smallest
  diff, but leaves the runner carrying the duplicated staging list that
  docs/d041 already says it should not own. Rejected.
- **Add a `ro:`/`rw:` prefix syntax to `DIRECTORY`.** Would restore a
  read-only reference mount, but every current use routes through
  `workload_rw`, and the prefix is a parser/quoting surface for a mode no
  caller needs. Rejected as speculative.
- **Keep an env toggle alongside the directories.** Two ways to say the same
  thing is the special case this record removes. Rejected.
- **Mount a directory at a caller-chosen container path
  (`HOST:GUEST`).** The workload API's `workload_rw host guest` already
  supports it, but the launcher's contract is "same path on both sides",
  which keeps the workdir/log paths self-describing. Rejected.
