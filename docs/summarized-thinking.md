# summarized-reasoning extension

Swap the model's raw chain-of-thought for a concise summary, inline.

## What it does

- Accumulates the **full** chain of thought during streaming (never shown raw).
- At `message_end`, makes **one** summarizer call over the complete CoT,
  grounded by a short snippet of the preceding user message / tool result.
- Replaces the stored `thinking` block with that summary (when enabled).
- The `reasoning-popup` extension can still show the live raw CoT as a progress
  indicator; summarized-reasoning never runs the summarizer through the agent
  loop, so its own tokens are not surfaced as thinking.

## Why summarize once, at turn end

A rolling, paragraph-by-paragraph summary drifts: each step only sees its own
snippet plus the previous (already lossy) summary, so decisions and open
questions quietly evaporate. Summarizing the complete CoT once — grounded by the
preceding context — produces one coherent summary and avoids the drift.

## Commands

| Command | Purpose |
|---|---|
| `/reasoning-summary` | Toggle summary replacement on/off (default ON). OFF keeps raw thinking in context for the next turn. |
| `/reasoning-summary-test` | Fire one summarizer call (no agent turn) to validate the pipeline. |
| `/reasoning-summary-model <provider/modelId>` | Switch the summarizer to a different model from the live catalogue; empty args reset to file/env/builtin. |

## Configuration (priority: env > `.pi/summarized-reasoning.json` > builtin)

The summarizer only uses models **already configured in pi's model registry** —
no providers are self-registered; a candidate is usable iff
`ctx.modelRegistry.find(provider, modelId)` resolves it (catalogue entry plus
working auth).

`.pi/summarized-reasoning.json` (flat object; all keys optional). The built-in
behaviour pulls from the **live llama-swap catalogue** on `:18080`, in order:
`01b-ctx125-unsloth/LFM2.5-8B-A1B-GGUF:Q8_0` (primary), then
`02b-ctx128-unsloth/gemma-4-E2B-it-qat-GGUF:UD-Q4_K_XL` (fallback), then
`opencode-go/mimo-v2.5` (emergency cloud fallback). The catalogue
model supplies `reasoning: true` (generated by
`openai-completions-gfx1030/generate-local-llm-models.yaml.mjs`), so the per-request
`enable_thinking:false` disable is emitted. A single explicit `provider`+`model_id`
overrides the candidates (it must still resolve in the registry).

```json
{
  "provider": "llama-swap",
  "model_id": "02b-ctx128-unsloth/gemma-4-E2B-it-qat-GGUF:UD-Q4_K_XL",
  "grounding_chars": 1200,
  "summarize_min_chars": 200,
  "hide_thinking_fallback": "summarize"
}
```

Environment overrides (highest priority):

- `SUMMARIZER_PROVIDER` + `SUMMARIZER_MODEL_ID` (pin a single explicit model)
- `SUMMARIZER_GROUNDING_CHARS`, `SUMMARIZER_MIN_CHARS`
- `SUMMARIZER_HIDE_THINKING_FALLBACK`

Built-in default uses the live llama-swap catalogue on `:18080` (auth configured
via pi's provider setup, `PEER_API_KEY` injected by `run.sh` from Infisical). If
no candidate model resolves in the registry (no LLM backend), the extension
disables itself for the session and leaves the raw chain-of-thought inline.

## `hide_thinking_fallback` and the `hideThinkingBlock` clash

Pi exposes `hideThinkingBlock` (settings.md § Model & Thinking, default
`false`). When ON, the interactive renderer shows a static "Thinking…" label and
does not feed thinking markdown to transformers.

This extension reads `hideThinkingBlock` from a `SettingsManager` built from
`ctx.cwd` (global `~/.pi/agent/settings.json` overridden by project
`.pi/settings.json`) and resolves the conflict via `hide_thinking_fallback`:

- `"summarize"` (default): force the summary visible inline, overriding the
  hide setting — the extension's purpose is to *replace* the hidden block with a
  useful summary.
- `"hide"`: defer to `hideThinkingBlock`; a hidden block stays hidden.
- `"raw"`: leave raw CoT inline (extension effectively disabled, but candidates
  are still resolved from the catalogue).

In all cases, when `hideThinkingBlock` is ON and fallback is not `"summarize"`,
the extension neither rewrites the stored thinking block nor surfaces a summary
via the markdown transformer.
