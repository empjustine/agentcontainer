# d229 — the patch transport is git's own series

**Status: landed, at both ends.** `./node-run.sh git/export-patches.mjs`
writes the commits a local branch carries and its upstream does not into
`<ordinal>-<full-hash>.git.patch` files; `git am --empty=keep` rebuilds the
branch from them, and `./node-run.sh git/apply-patches.mjs` is that apply with
the rollback and the report handled.

## Problem

"Give me what is not on origin yet" has three tempting answers, and two of them
lose information. `git diff upstream..HEAD > out.patch` is one flat change:
the commits, their authors, their messages and the order they arrived in are
gone, and a binary blob degrades to "Binary files differ". A hand-named series
(`fix1.patch`, `fix2.patch`) renames itself the moment a commit is reordered
or its message edited, and its apply order is whatever the shell glob says.

Publishing such a series into a directory has the shape every other generated
artifact in this tree has: a run that dies halfway leaves something that reads
as a series and is not one.

## Decision

The format is git's own. Git already has one — a second format would be a second
thing to keep true — and `git format-patch` writes an email-shaped patch
(`From <sha>` line, author, date, subject, diffstat, diff) that `git am`
consumes back.

- **One file per commit, each one an mbox git wrote.** The standardised
  single-file form of this content is the same mbox concatenated
  (`git format-patch --stdout`). Splitting it costs nothing — the format is
  designed for it — lets the file name carry the commit, and lets a partial
  series apply.
- **Naming is `<ordinal>-<full-hash>.git.patch`,** the ordinal zero-padded to
  the series width. A lexicographic sort of the directory is the apply order,
  the ordinal survives a re-export, and the hash resolves without the
  repository. The subject stays out of the name: it carries slashes, spaces and
  whatever length a commit message wants.
- **The base is the branch's upstream, then `origin/HEAD`.** The first answers
  "not pushed yet"; a branch that has never been pushed has no upstream, and the
  remote's default branch answers the same question. `--base REF` names any
  other starting point. Both attempts are ref lookups whose exit status is the
  answer — nothing is probed first (docs/d228).
- **`--binary` is not optional, and the bytes must be git's.**
  `format-patch` omits binary hunks without it, and a patch that cannot carry
  the blob cannot reproduce the commit. The series is therefore generated by git
  INTO its destination directory: this unit's `git()` helper decodes stdout as
  UTF-8, and a diff line holding a text-ish blob's non-UTF-8 bytes comes back
  with U+FFFD in it — measured, and the applied file then differs from the
  commit by exactly those bytes.
- **`--no-signature`** drops the tool-version trailer, the only part of a
  patch file that describes the exporting host instead of the commit.
- **Publication is a swap** (docs/d228 R8-R10): the series is built in
  `.<name>.new-<pid>` beside the target and moved into place with one
  `rename`; an occupied target moves to `.<name>.old-<pid>` and is dropped
  only after the new one stands, and a failed second rename puts the old one
  back. A name that already leads with a dot keeps the single dot it has, or the
  litter would not line up with the series it belongs to. A crashed run leaves
  names a farm walk ignores, and the next run removes the staging name and
  restores a series that was moved aside (R11).

Applying is `git am --empty=keep <dir>/*.git.patch`. `--empty=keep` because
a commit may change nothing, and an export that dropped those would not
reproduce the branch; `git am` otherwise stops on an empty patch.

## Applying the series

The series is plain `git am` input, so a receiver needs nothing but git:

    git am --empty=keep <dir>/*.git.patch

`git/apply-patches.mjs` is that command with the failure handled, and the
handling is the reason it exists: the receiver is where a transport can leave
the worst damage, because the alternative to "applied" is not "unchanged" but
"half applied".

- **The whole series goes in ONE `git am` invocation.** Git keeps one
  `rebase-apply` state per run, so one `git am --abort` restores everything
  that run did — the commits it already made included — instead of leaving a
  partly patched branch (docs/d228 R8/R11).
- **No pre-flight check.** A `git apply --check` that then authorizes a real
  apply is the just-in-case probe docs/d228 forbids, and it is wrong even when
  it passes: a hunk the check refuses is exactly what `--3way` resolves.
- **A failure is a rollback, not a report.** `git am`'s non-zero exit is
  followed by `git am --abort`, whose own exit status says whether there was
  anything to undo. The head is then asserted against the one the run started
  from, and a difference is reported rather than smoothed over: it means an
  apply was already in progress and the abort restored THAT run's starting point
  (docs/d228 R7).
- **A dirty work tree is git's refusal, not this tool's.** `git am` declines to
  start, so the local edit is still there afterwards. The test asserts the edit
  survives, because "refused" and "wrecked" read the same from the exit status.
- **`--3way` is the store-and-forward case.** A series generated on one host
  and applied to a tree whose context has drifted merges instead of failing,
  provided the receiving repository holds the pre-image blobs — the same
  history. A literal diff carries no objects to merge against, so a tree without
  that history gets git's per-patch "Repository lacks the necessary blob", and
  the fix is the exporting side's base. Measured: a patch rewriting line 10,
  with the receiver's drift on line 7 — inside the hunk's context window — is
  refused by a plain apply and merged by `--3way`, which keeps both lines.
- **Success prints an undo.** `git reset --hard <head-before>` is the receiving
  side's reversal for a series it accepted and does not want.

## Verification status

`git/tests/git-export-patches.test.mjs` — 10 tests, all passing, and the
central one is a round trip rather than a file listing: a fixture whose
`feature` branch is five commits ahead of a bare `origin` (a text append, an
empty commit, a blob with NUL bytes and bytes that are not valid UTF-8, a
rename, a mode change) exports, applies onto a fresh clone of that origin with
`git am --empty=keep`, and lands on the same tree as the branch. The other
nine pin the naming and apply order, the `origin/HEAD` fallback, `--base`,
the swap over an existing series, the crashed-run recovery (a moved-aside series
is restored and a dead run's staging half is removed), a failed run leaving the
previous series untouched, "nothing to export" writing nothing, a non-repository
being named as such, and `--help`.

`git/tests/git-apply-patches.test.mjs` — 9 tests, all passing. Every failure
case asserts the same three things (the branch is where the run found it, the
work tree is clean, the local work is intact) rather than the wording of a
message: the round trip onto a fresh clone, a series already applied, a conflict
halfway through (patch 1 committed, patch 2 refused — the rollback has to drop
that commit too), a dirty tree whose edit survives, `--3way` over drifted
context, an empty series, a missing directory named with its ENOENT, `--json`,
and `--help`.

Two measurements behind the shape: `git am --allow-empty` is rejected by git
2.56.1 with "Resolve operation not in progress" while `--empty=keep` applies
the whole series, and the UTF-8 pipe was caught by a tree comparison — the
first version of the export decoded `format-patch`'s stdout and rebuilt
`blob.bin` 52 bytes longer than the committed one.

## Consequences

- **A merge commit is not in the series.** `format-patch` renders one only as a
  combined diff (`--cc`), which `git am` cannot replay. Its content still
  arrives, because it came in through the non-merge commits the merge brought,
  and the export warns with the count when a range holds one.
- **The published directory is derived data.** Its contents follow the range on
  every run, and a rerun replaces the whole directory, so a stale patch cannot
  outlive the commit it describes. Nothing in it is hand-edited.
- **An empty range is a success.** Zero commits export nothing, touch no
  directory, and exit 0: a sweep script asks "is there anything to hand over",
  and the answer being "no" is not a failure.
- The export never writes to a remote and never fetches: it reports what the
  local refs say, so a stale `origin/<branch>` produces a longer series. That
  is the operator's `git fetch` to make.

- **A transported commit is not the same object.** `git am` keeps author,
  author date and message, and writes a new commit with a new committer and a
  new hash, so a round trip reproduces the tree and the shape of the history,
  not the commits. A workflow that compares SHAs across the transport compares
  two different objects.

## Alternatives rejected

- **Reimplementing the format with a library** (jgit, dulwich). Both can read
  and write patches, and both would be a second implementation of a format git
  owns: mbox framing, byte-exact binary literals, the `--3way` fallback,
  empty commits, and `git am`'s abort semantics, all kept in step with the git
  that produced the series. The one-line `git am` inherits every one of those
  from the same program, and git is runtime tooling for this folder rather than
  a dev-only dependency (docs/d226).
- **One `git diff` file.** Loses authorship, messages, commit boundaries and
  binary content, which is what the series is for.
- **`git bundle`.** Genuinely git-native and single-file, and it does carry
  history — but it is a transport for a repository, not text a person reviews in
  a diff view, and a bundle applies as a fetch rather than commit by commit.
- **`git format-patch --stdout` as the only output.** The same bytes as the
  series in one file, but then the file name says nothing about which commit is
  inside, and a failure halfway through the apply leaves no way to name the
  boundary.
- **Subject-named files** (`0001-fix-the-thing.patch`). The order survives, the
  identity does not, and the name changes when the message does.
- **Writing into the target directory in place.** The partial series is exactly
  the broken intermediate state docs/d228's transaction rules exist to prevent.
