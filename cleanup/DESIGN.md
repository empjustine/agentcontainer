# Contract for the reproducible-artifact cleaners

This is the single home for the rules the `clean-*.sh` scripts obey. The
[README](README.md) is usage and the script inventory; the code is the source
of behavior. If the contract and the code disagree, the code is wrong until
proved otherwise, or this document is stale.

## Objective

Recover space in a work tree by removing **reproducible artifacts** without
dirtying a repository and without deleting material whose loss is
irreversible. The cleaners are tree-agnostic: the root is a CLI argument and
defaults to the current directory.

## Requirements

- **R1 — one script per type.** Each `clean-*.sh` covers exactly one artifact
  type; `run-all.sh` only iterates and forwards arguments. Maintenance is not
  cleanup: `git-gc.sh` stays outside the `clean-*.sh` glob and outside
  `run-all.sh`.
- **R2 — uniform CLI.** `./clean-<type>.sh [--apply] [root]`. The root
  defaults to `$PWD` and is normalized to an absolute path before the git
  guards run.
- **R3 — dry-run is the default.** Without `--apply`, nothing is removed: each
  candidate is logged with its size and a summary closes the run.
- **R4 — stable structured report.** Output is the repo's `log.sh` JSON
  format. Events: `would remove`, `removed`, `remove failed`,
  `skipped tracked path`, `kept path without a git signal`, and one
  `cleanup summary` carrying `kind`, `mode`, `items`, `size_kb`,
  `skipped_tracked`, `warned`, `reported_dirs` and `failed`.
- **R5 — idempotence.** Re-running immediately after `--apply` reports zero
  items.
- **R6 — exit status.** `0` success (including `--help`), `1` missing or
  unresolvable root, `2` unknown option.
- **R7 — dependencies.** POSIX `sh` plus the core utilities the scripts use
  (`find`, `du`, `awk`, `sed`, `date`, `mktemp`, `dirname`, `basename`,
  `rm`) and `git` (Linux/GNU accepted). No network, no installation.

## Safety invariants

The guards run in this order for every candidate:

- **I1 — tracked is never removed.** If git tracks any file inside the path,
  the path is skipped and logged. Some repositories version generated
  artifacts on purpose; removing them would dirty the repository and destroy
  the committed copy.
- **I2 — in-repo with no git signal is kept.** If the path is inside a
  repository but neither tracked nor ignored, it is logged as
  `kept path without a git signal`; it may be source that merely has an
  artifact-shaped name.
- **I3 — ignored is removable.** The repository itself declared the content
  disposable.
- **I4 — outside a repository is removable.** There is no git signal to read;
  the dry-run is the protection.

Two details keep the guards honest:

- `git check-ignore` needs the trailing-slash retry: a pattern such as
  `dist/` matches only a directory, so the bare path passes cleanly.
- I2 and I4 are heuristics. Reviewing the dry-run list before `--apply` is an
  operator requirement, not something the script can prove.

## Per-script boundary

| Script                     | Owns                         | Prunes                | Boundary note                                                       |
| -------------------------- | ---------------------------- | --------------------- | ------------------------------------------------------------------- |
| `clean-python.sh`          | Python caches                | venvs, `node_modules` | pyc inside a venv belongs to the venv                               |
| `clean-venvs.sh`           | whole virtualenvs            | `node_modules`        | only known venv names; lowercase `env` is a source name, not a venv |
| `clean-node-modules.sh`    | `node_modules`               | —                     | nested `.pnpm` goes with the parent; do not list it separately      |
| `clean-pnpm-store.sh`      | top-level package stores     | `node_modules`        | `.pnpm` inside `node_modules` belongs to the script above           |
| `clean-js-builds.sh`       | JS/TS build and cache output | venvs, `node_modules` | `dist`/`build`/`out` are generic; I1–I3 are mandatory               |
| `clean-coverage.sh`        | coverage reports             | `node_modules`        | regenerated by `--coverage`/`--cov`                                 |
| `clean-os-junk.sh`         | OS junk                      | `node_modules`        | `._*` directories are reported only                                 |
| `clean-zone-identifier.sh` | NTFS/WSL sidecars            | —                     | a tracked sidecar is still protected by I1                          |
| `git-gc.sh`                | git object maintenance       | —                     | outside `run-all.sh`; default reflog grace period, no `--prune=now` |

## Logging

The unit carries its own copy of the repo logger at `lib/log.sh` (a copy unit
keeps its kernel; d113). `lib/cleanup.sh` sources it with
`LOG_TOOL=cleanup`. There is no ad-hoc progress `printf` in a cleaner: a
per-path event is the report, and the summary is one event. The `--help` text
is the only plain-text output.

## Tests

`tests/cleaners.test.sh` is hermetic: it creates a tree under `mktemp`, makes
three repositories and one plain directory, and asserts the guards, the
dry-run/apply split, idempotence, exit statuses and `run-all.sh` membership.
The repo-wide `./test.sh` runs it through the `*/tests/*.sh` glob.

## Acceptance

- `sh -n` on every script.
- `cleanup/tests/cleaners.test.sh` passes.
- `shellcheck -x` passes over every tracked script.
- A dry-run lists the candidates and changes nothing; `--apply` removes only
  I3/I4 candidates; a second run reports zero items.
- Exit codes are 0/1/2 as specified.
- `git-gc.sh` never appears in `run-all.sh` output.

## Non-goals

- Deciding what is reproducible outside this tree. The operator reviews the
  dry-run.
- Deleting material whose loss is irreversible, or versioned generated
  artifacts.
- Global package-manager caches (`uv`, `npm`, `pnpm`, `yarn`, `pip`,
  `go`). Those are host state, not a tree; they belong to the host maintenance
  surface, not this unit.
- Automatic volume/artifact reconciliation after a cleaner changes what exists.

## Rationale facts

- Generated artifacts are sometimes tracked on purpose. I1 protects the
  committed copy; the summary reports how many tracked paths were skipped.
- A missing `.gitignore` can leave a generated directory with no git signal at
  all. I2 keeps it and warns instead of guessing.
- `git gc` preserves a commit reachable only from the reflog and prunes only
  objects with neither ref nor reflog. The default two-week grace period is the
  safety net for an interrupted operation; `--prune=now` removes that net, so
  `git-gc.sh` never uses it.
